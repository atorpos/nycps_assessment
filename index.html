Data note: The 2019 figures for school 99X999 come from the assessment prompt. Other school and year combinations use illustrative data only. The Live API option requires the included server.js application and its database. If the API is unavailable, an error message appears and the previous chart values are dimmed.

i.What the API returns

Each API response contains one school and year, four benchmark labels, and separate values for All Students and SWD. The JSON example below updates when the selected filters change.

The database stores one record per school, year, student group, and benchmark. A composite primary key prevents duplicate records for the same combination.

ii.Front-end changes

  1. The three filters live in one <form>. Any change loads new data; Reload repeats the last request.
  2. fetch() the endpoint, check the JSON has two arrays of four finite numbers, then swap each chart's data and call chart.update(). Create each Chart.js instance once and update its existing dataset when new data arrives.
  3. Assign an identifier to each request. Ignore responses from earlier requests if users change their selection before the request finishes.
  4. Loading and errors are reported in a role="status" line. On an error the previous bars are greyed out, so they can't pass for the new selection.

iii.Back-end steps

  1. Create credit_accumulation in PostgreSQL (schema.sql above) and load the figures.
  2. Add an Express app with a pg connection pool and one route: GET /api/credit-accumulation?schoolId=…&year=….
  3. Check schoolId and year before going near the database, and send them as bound parameters ($1, $2). The SQL string is never built from user input.
  4. Pivot the rows into the two four-value arrays the charts expect. Answer 404 when the school and year have no rows, and 422 when some benchmarks are missing.
  5. Serve this page from the same Express app. The browser then calls the API on its own origin, and no CORS setup is needed.
